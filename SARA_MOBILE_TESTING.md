# SARA Mobile Testing Plan

Date: 2026-08-22
Status: audit plan; implementation tests do not exist yet.

## Existing Baseline

Run the existing desktop checks before and after mobile work: `npm run build`, `npx tsc --noEmit`, focused Node tests, focused Python tests, and startup/health checks. Existing desktop behavior is a release gate.

## Planned Test Groups

- Shared contracts: auth, device, capability, task, conversation, memory, event, result, and error schemas.
- REST: login/refresh/logout, profile, conversations, memory, tasks, devices, settings, notifications, and capability discovery.
- WebSocket: CONNECTING, AUTHENTICATING, READY, CONNECTED, RECONNECTING, DISCONNECTED; live chat/audio; task events; duplicate/reordered event handling.
- Authentication: expired access token, refresh rotation, logout/revocation, unknown device, replayed registration, TLS configuration, and rate limits.
- Device routing: camera to Android, browser/shutdown/file automation to Windows, offline device, ambiguous device, unavailable capability, and explicit target handling.
- Memory synchronization: desktop and mobile see the same backend memory; offline cache never becomes an authority; conflict/retry behavior is deterministic.
- Task recovery: mobile disconnect, Gemini disconnect, backend restart, Desktop Agent restart, duplicate submit, cancellation, confirmation, and final verified result.
- Permissions: camera, microphone, notifications, files, screen capture; granted, denied, permanently denied, revoked while running.
- Voice: microphone lifecycle, streaming latency, interruption, resume, output playback, no microphone permission, network loss, and wake-word limitations.
- Camera/vision: frame sampling, resolution limits, stop/release, privacy state, upload failure, backend analysis failure, and no continuous upload without user action.
- Security: no Gemini key in APK/assets/logs, redacted device events, backend authorization for every tool/task, confirmation cannot be generated by assistant text.
- UI parity: screenshots at representative phone sizes compare information hierarchy, colors, typography, status indicators, chat, task cards, confirmation, camera, settings, memory, and notifications to the existing SARA renderer.
- Desktop regression: Electron startup, Windows automation, Desktop Agent health, existing Gemini Live, memory, ToolRouter, browser, camera, and file tests.

## Acceptance Principle

A test passes only when the action is completed by the correct device and the result is verified. Opening a screen, accepting a command, or queuing a task is not equivalent to completing the requested real-world action.
